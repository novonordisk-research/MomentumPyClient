# MomentumPyClient Improvements

## Maintainability suggestions

| # | Description | Impact | File / Area | Status |
|---|-------------|--------|-------------|--------|
| 1 | **No tests exist.** The `pyproject.toml` lists `pytest` as a dev dependency but there are zero test files in the repository. Every change must be manually validated against a live Momentum instance. This makes refactoring very risky and slows debugging. At minimum, unit tests using `unittest.mock.patch` to mock `requests.get` and `requests.post` should cover the token-refresh logic, `run_process` XML generation, `reformat_container_nests`, and `get_containers_with_attributes` filter behaviour. | High | Entire package | Open |
| 2 | **Module-level singleton in `ui.py` makes it non-importable without a live Momentum server.** Lines 279–287 of `ui.py` execute `_stm = StreamlitMomentum()` at import time, which immediately calls `get_container_definitions()`. This means any import of `MomentumPyClient.ui` fails if Momentum is unreachable (CI pipelines, offline development, unit tests). The fix is to lazily initialise `_stm` on first use, e.g., using a module-level `_stm = None` and a `_get_stm()` accessor. | High | `ui.py:279–288` | Open |
| 3 | **Return-value schemas are undocumented.** Methods like `get_containers()`, `get_nests()`, `get_devices()`, `get_item_attribute()` return dicts/lists whose key names are entirely undocumented in the code. Downstream code makes many assumptions about key names (e.g., `c["Inventory"]["ItemId"]`, `n["Content"]`, `d["IsInstrument"]`). A `TypedDict` or dataclass definition for each response shape — or at minimum a docstring table of keys — would prevent breakage when the Momentum API changes a key name and would enable IDE autocomplete. | High | `ws.py` all query methods | Open |
| 4 | **`_send_post_request` has three code paths based on data type with inconsistent header usage.** When `data` is a `dict`, `self._headers` is used (no Content-Type). When `data` is a `list`, `headers` (with `Content-Type: text/plain`) is used. When `data` is anything else (bytes/string), `headers` with Content-Type is used. There is also a locally constructed `headers` variable that duplicates `self._headers` + Content-Type. This logic is hard to reason about, and a future change to one branch may silently break another. The correct fix is to document which endpoints require which Content-Type and split into explicit methods or use a `content_type` parameter. | Medium | `ws.py:163–200` | Open |
| 5 | **`run_process` accepts both dict and list for `variables`, creating two complex code paths.** Lines 541–584 of `ws.py` have an `if isinstance(variables, dict)` branch and an `else` branch for list-of-dicts, each with its own iteration logic. The list-of-dicts branch has a bug (see Bugs table, item 3). Most callers use the dict form. The list form could be removed or deprecated; if retained, it should share a common XML-serialisation helper to avoid duplication and divergence. | Medium | `ws.py:541–584` | Open |
| 6 | **`reformat_container_nests` is duplicated between `ws.py` and `utils/util.py`.** The Streamlit app has its own copy of this function in `utils/util.py` (lines 129–188) that is subtly different: it does not handle the `IsStack`/`StackContents` case for empty stacks (it always iterates `StackContents` without an empty-check), and it does not track `StackName` with the same logic. Having two versions means bug fixes in one are not applied to the other. The `ws.py` version should be the sole implementation; `utils/util.py`'s copy should be removed and the call sites updated to use `ws.reformat_container_nests`. | Medium | `ws.py:721–803`, `utils/util.py:129–188` | Open |
| 7 | **`ui.py` module-level `get_nests()` function shadows the instance method and is broken.** The module-level `get_nests()` (line 291) is a `@st.cache_data(ttl=60)` function but calls `_stm.ws.get_nests(_stm)` — passing `_stm` as an argument to a method that takes no arguments. This raises `TypeError`. The function also duplicates the instance method `StreamlitMomentum.cached_get_nests` (TTL 10 s). The module-level function should either be removed or fixed to call `_stm.ws.get_nests()` without arguments; the TTL difference between the two needs a conscious decision. | Medium | `ui.py:291–292` | Open |
| 8 | **`get_instrument_nests` does not handle all nest naming conventions.** The method handles `Device:Column:Nest N` (3-part) and `Device:NestName` (2-part) patterns but has partial or no support for bucket-style nests (`Bucket N`) and explicitly skips `Stack1` nests with a `continue`. The comment "TODO make this work if there is a single Nest or nests are named 'Bucket N' or 'Stack N'" has been present since early commits. This limits use of `get_instrument_nests` for any instrument that does not follow the standard naming conventions. | Medium | `ws.py:671–693` | Open |
| 9 | **Workunit name generation (`"Work Unit " + days-since-2020`)** is repeated in both `run_process` and `run_experiment` without extraction into a helper. If this naming scheme changes, it must be updated in two places. | Low | `ws.py:507–511, 610–615` | Open |
| 10 | **`ui.py` is commented out of `__init__.py` but not documented.** The `__init__.py` comment `# from .ui import StreamlitMomentum` suggests intentional exclusion, but no docstring or comment explains why the UI module is not exported. New developers may assume `from MomentumPyClient import StreamlitMomentum` should work. A comment explaining the reason (optional Streamlit dependencies, module-level side effects) would prevent confusion. | Low | `__init__.py:2` | Open |

## Bugs and fragilities

| # | Description | File / Line | Status |
|---|-------------|-------------|--------|
| 1 | **`get_process_variables`: dead code branch when `process_id > 0`.** At line 409, `url` is assigned to `self.url + f"/momentum/variables?processId={process_id}"`. However, at line 415 (outside the `if` block), `url` is unconditionally reassigned to `self.url + f"momentum/variables?process={process_id}"`. The line-409 assignment is always overwritten and never used, so passing `process_id > 0` has no effect on the URL. The `else` branch on line 411 also does not assign `url`, so `url` would be undefined if `process_name=""` and `process_id=0` and the process is not found in the list. Fix: restructure so the `if process_id > 0` branch sets `url` correctly and skips the process list lookup, with a proper `else` that builds the URL from the looked-up `process_id`. | `ws.py:408–416` | Open |
| 2 | **`run_experiment` hardcodes `iterations="15"`.** The `iterations` parameter is not exposed in `run_experiment`'s signature. Every call to `run_experiment` will attempt 15 iterations regardless of the caller's intent. This is almost certainly a development leftover. The fix is to add an `iterations: int = 1` parameter. | `ws.py:628–630` | Open |
| 3 | **`run_process` list-of-dicts path: `variable["values"]` uses wrong case.** At line 572, the code accesses `variable["values"].split(";")` (lowercase key) when splitting a semicolon-separated string. The dict key is `"Values"` (uppercase V, consistent with the rest of the codebase). This will raise `KeyError` when a `Values` entry is a semicolon-separated string and `run_process` is called with a list-of-dicts. The dict-based path (the more common path) does not have this bug. Fix: change `variable["values"]` to `variable["Values"]` on line 572. | `ws.py:572` | Open |
| 4 | **`run_process` list-of-dicts path: `variable["Iteration"]` should be `value["Iteration"]`.** At line 577, inside the loop `for value in values`, the code checks `if "Iteration" in variable` and reads `variable["Iteration"]`. This should check `value` (the inner dict), not `variable` (the outer dict). As a result, per-value iteration overrides in the list-of-dicts format never take effect. Fix: change `variable["Iteration"]` to `value["Iteration"]` on line 577–578. | `ws.py:576–578` | Open |
| 5 | **`ui.py::get_nests()` raises `TypeError` at runtime.** The module-level cached `get_nests()` function calls `_stm.ws.get_nests(_stm)`, passing `_stm` as a positional argument. `Momentum.get_nests()` accepts no arguments. This raises `TypeError: get_nests() takes 1 positional argument but 2 were given`. Fix: change the call to `_stm.ws.get_nests()`. | `ui.py:292` | Open |
| 6 | **`get_barcodes` crashes if any container has `Inventory == None`.** Line 702 accesses `c["Inventory"]["TemplateName"]` without checking whether `c["Inventory"]` is `None`. Containers being transported by the robot can have `Inventory == None`. This raises `TypeError`. Fix: add `if c["Inventory"] is None: continue` before the template check. | `ws.py:702` | Open |
| 7 | **`url` variable may be undefined in `get_process_variables` when `process_id=0` and `process_name` is not found.** If `process_id=0` and `process_name` is provided but does not match any process in `get_processes()`, the `for p in processes` loop completes without assigning `process_id` to a non-zero value. Line 415 then builds a URL with `process=0`, which is likely an invalid query. There is no guard or error message. | `ws.py:402–416` | Open |
| 8 | **`ui.py::StreamlitMomentum.__init__` calls `get_container_definitions()` during construction, which calls the Momentum API.** If the API is unreachable at import/startup time, the module fails to initialise and the entire Streamlit app crashes. There is no error handling around this call. A try/except that falls back to an empty colour dict would make the app more resilient. | `ui.py:64–69` | Open |
| 9 | **`20_ABS_RestoreReset.py` and `21_ACSINS_RestoreReset.py` fetch all container attributes in a serial loop instead of using `get_containers_with_attributes`.** Lines 20–23 of each file loop over all containers calling `get_item_attribute` individually. For a large inventory this is very slow (one HTTP call per plate). `get_containers_with_attributes()` provides the same result with async fan-out and is significantly faster. This is not a bug in MomentumPyClient itself, but it is a fragile usage pattern in the app that should be corrected. | `pages/20_ABS_RestoreReset.py:20–23`, `pages/21_ACSINS_RestoreReset.py:20–23` | Open |
| 10 | **`06_CompleteTestRun.py` and `25_test.py` call `get_containers_with_attributes()` and then re-fetch attributes per container in a loop.** Line 43 of `06_CompleteTestRun.py` calls `stm.ws.get_containers_with_attributes()` (which already includes attributes), and then line 51 calls `momentum.get_item_attribute(itemId)` again for each container. The second fetch is redundant and doubles API traffic. Same pattern in `25_test.py:36` and `25_test.py:44`. | `pages/06_CompleteTestRun.py:43–54`, `pages/25_test.py:36–48` | Open |
| 11 | **`reformat_container_nests` does not add an empty slot record when a stack has no contents.** When `n["IsStack"]` is `True` and `len(n["StackContents"]) == 0`, the `ws.py` version adds a single placeholder slot with empty Barcode and Template. The `utils/util.py` version iterates `StackContents` directly without an empty check and would simply add no records. Both behaviours may or may not be correct depending on how the Plotly chart handles empty stacks, but the discrepancy between the two copies means the chart may render differently depending on which function is called. | `ws.py:766–776`, `utils/util.py:162–166` | Open |
| 12 | **`add_inventyory_items` method name typo is permanent API surface.** The typo ("inventory" → "inventyory") is embedded in the public method name, in `momentum_obsolete.py`, and in call sites throughout the Streamlit app. Any attempt to rename it is a breaking change requiring coordinated updates across all consumers. A deprecation wrapper with the correct spelling pointing to the old name (or vice versa) would allow gradual migration without breaking existing code. | `ws.py:282`, `03_orders.py:343` | Open |
